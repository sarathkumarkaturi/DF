# Experiment 3 – Password Capturing Using Wireshark

## Aim

To capture and analyze HTTP network traffic using Wireshark and observe the transmission of test login form data in an authorized laboratory environment.

## Software Required

- Wireshark 4.6.7
- Web Browser
- Local HTTP Test Application

## Introduction

Wireshark is a network protocol analyzer used to capture and analyze network packets.

In this experiment, Wireshark is used to capture HTTP traffic generated by a locally hosted test login page. The captured packets are then filtered and analyzed to identify the HTTP GET and POST requests associated with the test login.

The experiment is performed on a local test environment using dummy credentials.

## Procedure

### Step 1: Open Wireshark

Open Wireshark and view the available network interfaces.

The Wireshark interface displays different network adapters available for packet capture.

For the local test application, the loopback traffic capture interface is used because the test website is running on the local system.

Select **Adapter for loopback traffic capture** and start the packet capture.

Wireshark begins monitoring network traffic generated by the local test application.

### Step 3: Open the Test Login Page

Open the locally hosted test login page in a web browser.

The test application is available at:

`127.0.0.1:8000/login.html`

The page contains a username field, password field, and Login button.

Enter the dummy credentials provided for the laboratory experiment.

### Step 4: Submit the Test Login

Click the **Login** button on the test page while Wireshark is capturing the network traffic.

The login request is transmitted from the browser to the local test application.

Return to Wireshark after submitting the test credentials.

### Step 5: Stop Packet Capture

After the login request has been captured, stop the packet capture in Wireshark.

The captured packets can now be analyzed.

### Step 6: Filter HTTP Traffic

In the Wireshark Display Filter bar, enter:

`http`

Press **Enter** to display the captured HTTP packets.

This helps identify the HTTP traffic generated during the test login.


<img width="1919" height="1199" alt="6" src="https://github.com/user-attachments/assets/7c0ad004-399c-4d88-94d2-4fecadabe1c5" />

### Step 7: Analyze HTTP GET Requests

To identify HTTP GET requests, enter the following display filter:

`http.request.method == "GET"`

Press **Enter**.

The filtered packets display the HTTP GET requests generated by the test application.


<img width="1919" height="1199" alt="7" src="https://github.com/user-attachments/assets/c5351eee-49e7-4e74-8e98-9521baa767a0" />

---

### Step 8: Analyze HTTP POST Requests

Clear the previous filter and enter:

`http.request.method == "POST"`

Press **Enter**.

The filtered results display HTTP POST requests generated during the test login.

Select the POST packet corresponding to the test login request.

Examine the packet details displayed in the lower section of Wireshark.

### Step 10: Examine the Form Data

Examine the HTML form data associated with the POST request.

The submitted test form fields can be observed in the captured HTTP request because the laboratory application uses unencrypted HTTP communication.

Only dummy laboratory credentials are used in this experiment.



---

## Observation

The following observations were made during the experiment:

- Wireshark successfully captured local network traffic.
- The locally hosted test application generated HTTP traffic.
- HTTP packets were identified using the `http` display filter.
- HTTP GET requests were identified and analyzed.
- HTTP POST requests were identified and analyzed.
- The login POST request contained the submitted test form data.
- The experiment demonstrates the security risk of transmitting sensitive information over unencrypted HTTP.

## Result

The HTTP traffic generated by the authorized local test application was successfully captured using Wireshark.

The HTTP GET and POST requests were identified using Wireshark display filters, and the POST request associated with the test login was successfully analyzed.

## Conclusion

The experiment demonstrated the use of Wireshark for capturing and analyzing HTTP traffic.

It also demonstrated why sensitive information such as login credentials should not be transmitted over unencrypted HTTP connections.

HTTPS should be used to protect login information during transmission.
